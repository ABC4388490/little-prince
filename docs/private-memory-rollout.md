# 私有记忆发布与验收

先在 Railway 确认服务实际关联的仓库、分支、启动入口及数据库。公网健康响应无法证明仓库关联；本次检查独立 Railway `/health` 在 12 秒内未响应，而同源聊天 `/api/health` 可用。

## 发布顺序

1. 先发布后端 PR，启动时创建匿名凭证与画像表，不删除旧数据。确认生产有持久化 Postgres 和 HTTPS。
2. 访问 `/health`，确认 `service: little-prince-memory`、`memoryAuthVersion: 1`。该响应不是数据库读写验证。
3. 分别申请两个临时匿名会话。自己的画像与会话可以读写；第二个会话读写第一个会话应返回 404；无凭证应返回 401。勿读取真实用户数据进行验收。
4. 发布前端 PR（包含之前的加载优化），检查手机首次打开、八章图片、明信片、B612 聊天与画像同步。首页不应签发凭证或加载云端历史。
5. 刷新后同一浏览器应复用凭证。切断记忆服务，仍可通过聊天接口获取回复，本地历史保留；不能把失败标成同步成功。

## 数据兼容与限制

旧随机 visitorId 不具备所有权证明，不能自动绑定到新凭证。旧数据库内容保留，需要单独制定所有权验证与迁移方案；用户本地历史不删除。

当前聊天发送走 `/api/chat`，前端把回复保存到本地；并未自动写入 `/conversations/<id>/messages`。新凭证保护画像与旧历史读取、以及后端已有的私有会话读写接口，但不等于实现完整云端同步。

清除浏览器数据、凭证失效或切换设备后，没有账号恢复机制。历史面板的清空按钮仅清除本地历史，不代表删除云端画像或聊天。界面若扩展云端删除，应实现对应的鉴权删除接口并说明删除范围。

旧版前端在后端升级后会停止无凭证同步；聊天与本地历史继续可用。安全回滚应保留后端鉴权，不恢复按访客 ID 读取私有内容的旧接口。
